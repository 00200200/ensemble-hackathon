Problem Statement
Quality context is the single greatest bottleneck in the evolution of AI-powered software
engineering. While Large Language Models (LLMs) have become remarkably adept at
generating code, their performance is strictly capped by the quality of the information they
are given. In a massive professional codebase, providing too little context leads to
hallucinations and broken logic, while providing too much irrelevant data - noise - clutters the
context window, increases latency, and degrades the model's reasoning capabilities.
Currently, IDEs struggle to programmatically determine exactly which snippets of code,
documentation, or metadata are relevant to a specific developer query. We don’t just need
smarter models; we need smarter ways to feed them.
Background & Context
We are entering the era of AI-native development. Tools like JetBrains AI have
revolutionized how we write code, but the underlying context collection mechanisms are still
in their infancy. This challenge, hosted in collaboration with JetBrains Research, focuses on
the frontier of Context Collection.
In professional software environments, a single repository can contain millions of lines of
code. When a developer asks, "How do I implement a new authentication provider based on
our existing pattern?" the IDE must instantly scan the repository to find relevant interface
definitions, utility classes, and configuration files. Industry research shows that the precision
of this "retrieval" phase is more influential on the final code quality than the size of the LLM
itself. By solving this, we empower developers to maintain flow state, reduce technical debt,
and leverage AI as a true pair-programmer that understands the specific nuances of their
unique codebase.
Challenge Objective
Your mission is to architect and implement a high-precision Context Collection Pipeline
specifically for Python environments. Using the provided datasets and the starter kit,

participants are expected to develop an algorithm or heuristic-driven system that identifies
the most relevant code context for a given programming task.

Evaluation Details
Evaluation Process
Submissions are evaluated through the following process:
1.​ Your submission is validated for format correctness
2.​ The composed contexts are used with three different models:
●​ Mellum by JetBrains
●​ Codestral by Mistral AI
●​ Qwen2.5-Coder by Alibaba Cloud
3.​ Each model generates completions based on your composed context
4.​ Completions are evaluated using the ChrF metric against the ground truth
5.​ The final score is the average ChrF score across all three models

Handling the submitted contexts
We use FIM (fill in the middle) when prompting models to do code completion. We handle
the preparation of a correct prompt for each model on the evaluation side: introducing
correct special tokens, arranging context, prefix, and suffix in a correct sequence based on
the model, and so on. We trim the user-submitted context from the left to fit the context
window of the respective model (8K tokens for Mellum, 16K for Codestral and Qwen).
We ask contestants to use the special file separator token from Qwen2.5 <|file_sep|>. When
prompting models, we replace it with the special token used by the specific model.

Metric: ChrF Score
The ChrF score is a character n-gram F-score that measures the similarity between
generated and reference text. It is particularly well-suited for code completion evaluation as it
captures both precision and recall at the character level, making it sensitive to small but
important differences in code syntax.

Leaderboard
The leaderboard displays the Average ChrF Score.
